## 一、PPT 的任务

这份 HTML 不是产品截图集，也不是把真实结果预先写死的静态页面。

它是一份“像 PPT 一样按页播放”的本地演示 HTML：可以用键盘或鼠标翻页，但现场结果仍然来自终端和浏览器的真实运行。

它只承担三件事：

1. 告诉观众这套工具解决什么问题；
2. 告诉主持人下一步要输入什么、运行什么、展示什么；
3. 在现场操作前后，帮助观众理解结果有什么用。

真实演示的主角是：

```text
主持人输入
    ↓
真实 Twelve Data API
    ↓
Python 现场扫描
    ↓
生成本次结果
    ↓
AI 根据结果解释：结果 / 证据 / 缺口 / 下一步观察
```

全程 15 分钟。HTML 负责宣传、讲解和切屏导航，终端和浏览器的真实操作才是现场证据。

安装步骤和 API 获取不属于现场演示内容。它们只写在公开版 README，路演时间全部留给五个工具和三日真实数据的解释。

## 二、制作原则

- 16:9 横屏，中文，短句，大字，少噪音。
- 必须是单页 HTML，优先采用纵向滚动和锚点导航，不做传统分页 PPT。
- 本地断网打开时不依赖外部 CDN、在线字体或在线图片。
- 在线 GitHub Pages 版本允许放视频链接、GitHub 链接和 API 官方文档链接。
- 页面顶部要有清晰导航：工具、真实演示、三日状态、安装使用、GitHub。
- 不放静态 HTML 截图作为主要演示内容。
- 不把 synthetic 离线数据包装成现场真实行情。
- 不要求观众理解 Python；现场主持人直接操作即可。
- 不堆代码，不展示 API Key，不展示本地私有路径。
- 不宣传预测涨跌、自动下单、高胜率或稳定收益。
- 每页只讲一个结论，标题直接说出这一页要让观众明白什么。
- 视觉要有冲击力，但不要做成密集的后台仪表盘或卡片墙。

## 三、建议单页网站结构

页面不是 9 张幻灯片，而是一个连续的宣传页面。每个模块既能滚动阅读，也要能通过顶部锚点快速跳转。

### 首屏｜让人第一眼知道它不是普通指标脚本

建议标题：

```text
AI 投研市场观察助手
把零散信号，变成可以现场运行、连续追踪、事后回放的观察过程
```

首屏必须有两个明显入口：

- `现场看它怎么跑`：跳到真实演示区；
- `下载并试用`：跳到 GitHub / README / Release 入口。

可放一个醒目的视频入口，但不要伪造视频缩略图或播放数据。没有最终视频地址时，使用明确占位符，不能编造链接。

### 模块 1｜它解决什么问题

保持三个短句：

- 指标很多；
- 报告很多；
- 但今天先看谁、连续几天发生了什么，容易丢。

### 模块 2｜真实工作流

```text
输入 5–10 只股票
    → Twelve Data 真实行情
    → 五个观察工具
    → 结构化结果
    → AI 解释：结果 / 证据 / 缺口 / 下一步观察
```

页面必须写清楚：网站本身不保存 API Key，不在浏览器前端直接暴露私钥；真实 API 运行在用户本地的 Python 入口中。

### 模块 3｜五个工具，各自解决什么问题

用五个纵向区块或清晰的五段内容，不要做密集后台卡片墙：

1. 多周期共振：60 分钟、日线、周线是否形成一致背景；
2. 五榜单：标的很多时，今天先看哪一组；
3. 背离 + TD9：价格和动能是否出现人工复核提示；
4. SKDJ：超跌、回调、超买或普通区属于哪类观察场景；
5. 状态链：这只股票跨几天走到哪一步，何时失效或继续观察。

每个工具只写“用途、输出、边界”，不要写长篇指标教程。

### 模块 4｜三天数据：从单日信号到连续状态

如果路演前已经实际生成今天、明天、后天三天数据，页面展示真实三日状态链；每处显示真实 `data_asof`，不手工写死结果。

```text
第 1 天：进入 OBSERVE
第 2 天：可能进入 BASE / 保持 OBSERVE
第 3 天：可能推进、失效或仍待观察
```

这部分是宣传网站的核心亮点：不是只展示一个漂亮指标，而是展示研究过程如何留下记忆。

### 第 9 页｜五个工具合在一起：指标是证据，状态是过程

这一页解释“后面的指标”应该怎样看，不再新增工具：

- 单日指标回答：今天有什么信号；
- 多周期指标回答：信号处在什么背景；
- 跨日状态回答：这只股票这几天走到哪一步；
- 失效条件回答：什么时候停止继续观察。

页面结论：五个工具各自提供证据，状态链把证据串成可回放的研究过程。

现场运行完成后，AI 按固定顺序解释本次结果：

```text
1. 结果：哪些标的进入优先查看顺序
2. 证据：来自哪些周期、榜单或信号
3. 缺口：哪些数据不足、规则仍属候选
4. 下一步：要继续观察什么，不给交易指令
```
